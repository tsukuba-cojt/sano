# 回覧板（かいらんばん）— 完全オフラインの BLE すれ違い通信アプリ

最終更新: 2026-11-20

## 1. 目的

地震などで携帯網も Wi-Fi も止まった被災地で、自治体や避難所の運営者が出す「〇〇避難所に水と毛布が届きました」のような短い文字情報を、**スマートフォン同士の Bluetooth（BLE）だけ**で広げるアプリです。
紙の回覧板が隣の家へ順に回るように、端末がすれ違うたびに情報が複製されて広がります（store-and-forward 方式）。

- サーバなし、インターネットなし、ペアリングなし
- iPhone / Android の両方に対応し、相互に通信できる
- 高齢者も使えるよう、市役所の掲示板のような分かりやすい画面

## 2. できること

| 機能 | 内容 |
|---|---|
| お知らせ | 見出し 40 文字・場所 40 文字・本文 1,000 文字。種別は物資・給水・炊き出し・避難所・医療・安否・交通・ライフライン・注意喚起など 16 種。有効期限が切れると自動で消える。発信者は取り消し・訂正ができる |
| グループ | 誰でも作成でき、6 桁の参加コード（QR も表示）が発行される。参加は番号を入れるだけ。参加中のグループのお知らせだけが表示されるので、他の自治体と混ざらない。作成者は 8 桁の発信者コードでスタッフを「公式」に昇格できる |
| すれ違い通信 | 近くの端末を自動で見つけて接続し、互いの「持っているお知らせの一覧」を交換して足りない分だけ送る。参加していないグループの分も中継だけはする（広がりやすさ優先）。バックグラウンドでも動作 |
| 住民からの知らせ | 住民は「本部に 知らせる」から「助けて（SOS）」「無事です」「家に います（在宅避難）」「困っています」を送れる。人数・場所（町名と目印）・ひとことを付け、無事・在宅避難だけ任意で名前を付けられる。本部・スタッフの端末だけに表示し、集計・絞り込み・「受け取りました」（まとめて返事も可）・文章でコピーができる。受け取りの返事は本人に届く |
| 安否確認 | 公式・スタッフはお知らせに「返事の ボタン」を付けられる。受け取った住民は「無事です」「家に います」「困っています」「助けて」で返事し、本部は安否確認ごとに集計できる |
| 通知 | 新しいお知らせが届くと、アプリを開いていなくても OS の通知で知らせる。本部の端末には SOS を緊急の通知で知らせる |
| 画面 | 本文 18pt・見出し 22pt、大きなボタン、白地に黒文字と青 1 色、下部タブ 3 つ（お知らせ／グループ／設定）、やさしい日本語。文字サイズは 3 段階 |
| 電池 | 残量 20% 以下で自動的に省電力（スキャン間隔を広げる）に切替 |

## 3. 仕組み

- **技術構成**: Flutter（画面と同期ロジックは Dart で単一実装）＋ BLE 層だけ Swift（CoreBluetooth）/ Kotlin（android.bluetooth）。外部 SDK・広告・解析ツールなし。
- **通信**: 1 件のお知らせはヘッダ 28 バイト＋本文。本文は災害用語の辞書付き圧縮で UTF-8 の 3 割程度に縮む（例: 300 文字 → 約 200 バイト）。接続後は GATT の書き込み（1 回 最大 512 バイト。続けて送るお知らせは詰めて書く）で、1 回のすれ違いにつき 64 KB まで転送。本文 100 文字のお知らせなら 400 件前後を 1 回で運べる。
- **ID と重複排除**: 各お知らせに 64 ビットの ID を付け、すれ違い時に「持っているもの」を交換して差分だけ送る。持っているものは Bloom フィルタで要約して送る（3,000 件で 24 KB → 約 3.6 KB）。端末には 3,000 件まで保存し、期限切れ → 書きなおされた古い版 → 未参加グループの古いもの の順に捨てる。
- **短いすれ違いでも大事なものから**: 会った瞬間に SOS と避難情報を先に渡し（中継中のほかの人の分も）、そのあと 取り消し → 無事・在宅避難 → 公式の給水・避難所など → 住民の投稿 → 訓練 の順に送る。送りきれなければ 2 秒後に続きを送る。受け取ったものはすぐ近くの別の端末へ渡す。
- **バックグラウンド**: iOS は Bluetooth のバックグラウンドモードと状態復元、Android は常駐サービス（再起動後も自動再開）。iOS 26 では Live Activity、一度つながった相手には自動再接続を予約。
- **調査に基づく設計**: iOS/Android の BLE 制約（Apple 公式ドキュメント・AOSP ソース）、BitChat・スマホdeリレー等の先行事例、デジタル庁デザインシステム、避難所運営ガイドライン、過去災害（熊本 2016・能登 2024）の通信途絶の実績を調べて要件と画面を決めた。

## 5. 既知の制約

- iPhone 同士が**両方とも画面消灯**だと互いを発見できない（Apple の仕様。Apple のエンジニアが「構造的制限で回避策なし」と回答）。片方がアプリを開いているか画面点灯中、または Android が近くに 1 台あれば届く。
- Android では「近くの人と情報を交換しています」という常駐通知が出る。機種によっては省電力設定の除外が必要。
- 暗号化・署名がないため、なりすまし投稿は技術的に可能。「公式」表示は参加コードと発信者コードの運用で守る（署名を後から足せるよう領域を予約済み。署名を付けても 1 件あたり約 72 バイト増えるだけ）。
- BLE の到達距離は 10〜30 m。歩いてすれ違う時間は 10〜25 秒程度。差分（数十件）と SOS・避難情報は 1〜3 秒で渡せる見込みだが、新しい端末が 1,500 件をそろえるには 30 秒〜1 分とどまる必要がある（Mac → iPhone の実測では 1,500 件が 28 秒、#121）。
- iPhone はアプリを上にスワイプして終了すると、開き直すまで中継しない。背面の iPhone は相手を見つけるまで数十秒〜数分かかることがある。
- 住民からの知らせは本部・スタッフの画面だけに出すが、暗号化はなく中継端末にも残る（表示上の分離）。いたずらの SOS は防げない（同じ人の送り直しを 10 分止めるだけ）。
