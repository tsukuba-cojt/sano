# 回覧板 ユースケースと仕様変更 v2

最終更新: 2026-10-16

本書は、回覧板（[01_requirements.md](01_requirements.md) / [04_ui_design.md](04_ui_design.md)）を「誰が・いつ・どこで・何を・どの画面で・何分以内に」使うかを 8 つの視点（防災課・避難所受付・住民・要配慮者・運び役・平時・医療とインフラ事業者・運用と技術）で洗い出し、現行仕様 v1 で「できる ◯ / 一部できる △ / できない ✕」を判定し、v2 で採用する仕様変更 C01〜C25 を確定したもの。各仕様変更は 実現性（feasibility）・利用者価値と単純さ（value）・運用とガバナンス（operation）の 3 視点で検証し、指摘をすべて取り込んだ。要件への反映は [01_requirements.md](01_requirements.md) v2（変更行の末尾に「（v2: C01）」）、画面への反映は [04_ui_design.md](04_ui_design.md) v2。

- 根拠の書き方: 文書は「01 §3.1 R-5」「04 §4.3」のようにファイル番号と節、コードは「message_store.dart _indexNew」のようにファイル名と識別子。
- 制約: BLE だけ・サーバなし・暗号化と署名なし・高齢者が使える UI（01 §2、§5、R-18〜R-24）。この制約の外に出る案は §4 で落とした。
- 規模: S = 半日、M = 2〜3 日、L = 1 週間超。

### 2.1 jumin-1 在宅避難の高齢者が、自宅にいたまま給水のお知らせを通知だけで知る

- 目標: 自分では何も操作せず、通知だけで「どこで・いつ」を知る
- 手順（現行）: 事前に「はじめに」と参加 → 何もしない → OS 通知「〇〇小学校で 給水を しています ／ 〇〇市 防災課 から」→ タップ → ホーム → カード → 詳細で「1人 2本まで」を読む
- 届くまでの時間: 給水開始の 1〜2 時間前まで。発信から 2〜8 時間以内
- 現行の判定: △。通知文に場所・本文がなくアプリを開く操作が要る（03 §4）。届け手も iPhone で消灯なら届かない（01 §5）。遅れて届くと残り時間が短い（R-4 給水 12 時間）。届いていないことが本人に分からない（04 §4.2 状態帯）

### 2.10 unyo-2 保存が満杯の端末どうしが 5 秒すれ違っても 1 件も運ばれない（unyo-3 を含む）
- 対象: 市グループ 5,000 人の住民 2 台（両方 3,000 件）。片方は MTU 23 の古い機種。unyo-3 は住民の安否投稿が公式を押し出す場面
- 状況: 5 日目、避難所の通路で歩きながら 5 秒
- 目標: すれ違い 1 回で公式の新着が移る。公式の避難所開設が 7 日間すべての端末に残る
- 手順（現行）: 操作なし（R-12）
- 届くまでの時間: 公式 1 件が 1 回のすれ違い（5 秒）で
- 現行の判定: △。目録 2,000 件 × 8 B = 16 KB を双方が先に送る（02 §4 手順 2〜3）。MTU 23 では目録だけで 10〜30 秒。目録 2,000 < 保存 3,000 で重複送信。削除順が役割を見ない（message_store.dart _evictionTier）

### 2.11 unyo-7 更新できない旧版と新版が混在すると網が分断する
- 対象: 1 年前に入れて自動更新を切った住民（v1）と最新版のスタッフ
- 状況: 発災当日からストア接続不可。将来版が新 kind・予約 flags・group_info の 5 番目フィールドを使う
- 目標: 旧版の端末でも新版の投稿を中継し、既存の notice は新旧の間で届き続ける
- 手順（現行）: 操作なし
- 届くまでの時間: 混在時も既存 notice の遅延が増えない

#### C01 「終わりました」「書きなおす」
- 詳細（04 §4.3）の発信者向け副ボタンを縦に「終わりました」「書きなおす」「取り消す（赤）」。避難情報には「終わりました」を出さない（解除は「書きなおす」で明示的に書く）。
- 「書きなおす」: 画面名「お知らせを 書きなおす」。元の種別・場所・見出し・本文で開き、上部に帯「前の お知らせは 消えて、この 内容に 置き換わります」。期限は種別既定から選び直す。「送る」で flags bit1・supersedes = 元 msg_id の notice を発信（AppController.postNotice に supersedes 引数、05 に AppController.supersede を追加）。tombstone は併発しない。
- 「終わりました」: 1 タップ＋確認「『〇〇公園の 給水は 終わりました』と 知らせます」。見出しは categories.dart の endTemplate（避難所「{場所}の 避難所は 閉じました」、交通「{場所}は 通れるように なりました」、給水・炊き出し・物資「{場所}の {給水}は 終わりました」、店舗「{場所}の 販売は 終わりました」、注意喚起は role=2 のとき「{場所}の 注意喚起は 解除されました」で、それ以外と他の種別は「{場所}の お知らせは 終わりました」。場所が空なら「{場所}の 」を省く）。本文「（10月12日 午後6時10分に 終わりました）」、期限 12 時間。
- 保持: supersedes 付き notice は tombstone と同じく「対象の expires_at + 24 時間」まで保持（retainUntil）。自身の期限後は表示しないが索引・目録・中継には使う（02 §5 と message_store.dart に追加。superseder が purge された後に旧版を初めて受け取る端末で旧版が復活する問題の対策）。
- 受信側の表示: 一覧では置き換えられた旧版を出さず、新版の行 1 に「書きなおし」または灰枠「終わりました」。詳細は区切り線の下に灰色で常時「前の 内容（午前8時 発信）: 〇〇公園で 給水を しています」（受信端末は見出しと発信時刻だけ。発信者本人の端末は場所・本文も）。送信後「訂正しました。近くの スマホに 広がります」。
- 役割: 書きなおし後の notice の role は元投稿と同じ端末区分。受信側は封筒の role が対象の role 以上の supersedes だけ適用（C10）。C10 と同じリリース。
- R-5 の注記: 「前の お知らせは 消えて」は受信済み端末では旧版が隠れるだけで本文は残る（本文を消すのは取り消し C20 のみ）。

#### C08 先出し・目録・削除順
- 同期手順に「1.5」: 相手の HELLO（通常 100 ms 以内、上限 5 秒）を受け caps bit3 が立っていれば、INVENTORY_END を待たずに、参加グループの group_info → tombstone → role=2 の notice（24 時間以内、取消済み・置き換え済みを除く）の順・created_at 新しい順で、合計 8 KB・16 件以内を MESSAGE で先に送る。前回この相手と同期した追加順 seq（StoredMessage にメモリのみで持ち、load 時はレコード順）から変わった分だけ。初対面なら最新分。先出し分はセッション上限 64 KB に含め、後段の missing 送信から除外。受信側は msg_id 既知なら無視（02 §4-4）。中継役同士（C17）でも同じ 8 KB・16 件。

#### C09 本部コード／スタッフコード
- R-10: ホストは本部コード（8 桁、先頭 1）とスタッフコード（8 桁、先頭 2）を配れる。本部コードで昇格した端末は役割=公式（青地白文字）でホストと同じ権限、スタッフコードで昇格した端末は役割=スタッフ（白地青枠、既存 RoleBadge）。先頭桁は誤入力検知と画面選択に使い、本部昇格の受理は C24 の code_digest 一致が条件。
- groups.dart JoinedGroup に staffCode・isStaff・senderName（グループごとの発信元名）を追加。postNotice の role は 公式 → 2、スタッフ → 1、それ以外 0。canPost に isStaff を足し、「参加者も 投稿できる」OFF でもスタッフは投稿可。
- 昇格画面は「本部コードを 入れる」「スタッフコードを 入れる」の 2 画面（グループ詳細の副ボタン 2 つ）。本部は確認「この端末を 本部端末に します」を挟む。本部昇格は code_digest 付き group_info を受信済みで一致したときだけ受理し、未受信なら「グループの 情報が まだ 届いていません。近くで もう一度 試してください」、不一致なら「番号が ちがいます」。スタッフコードはダイジェスト未受信でも受理するが role=1 と投稿権のみ。
- 昇格時に「この グループでの 発信元名」（必須、48 バイト以内）。初期値は公式ならグループ名「〇〇市 防災課」、スタッフなら設定の表示名。説明「施設名・部署名を 入れてください（例: 〇〇総合病院、〇〇小学校 受付）。個人名は 入れないでください」。投稿の sender_name に使う（設定の表示名は住民投稿用に残す）。

#### C12 相対期限・時計
- 02 §2 の「expires_at が受信時刻より過去 → 破棄」を次に変える。受信時に破棄するのは「ttl = expires_at − created_at が 0 以下または 30 日超」のときだけ（「created_at が 24 時間以上未来 → 破棄」は入れない。進んだ時計も同じ頻度で起きる）。
- 受信側は local_expiry = receivedAt + ttl を正とし、expires_at を自端末時計と比べない。中継送信時に expires_at := created_at + (local_expiry − now) と書き換える（offset 19 の 4 B。msg_id は expires_at を含まないので合法。wireBytes キャッシュは送信時に再生成）。残り時間は縮む一方なので「中継ごとに延びる」は起きず、総寿命 ≤ 元の TTL（operation 視点の延長上限は自動的に満たす）。02 §2 の「最初に受け取った値で固定」から expires_at を外し、N-4 を「相対優先」に改める。v1 端末は短くなった絶対 expires_at を見るだけなので相互運用する。
- 書く画面: 端末時計が 2026 年 1 月 1 日以前（epoch 0 に丸まる、epoch.dart）、または TIME フレームの中央値との差が 24 時間を超えるとき、「送る」の前に赤い注意「この スマホの 時計が 合っていません（2026年1月1日）。時計を 直してから 送ってください」＋副ボタン「設定を 開く」（既存 openAppSettings）。「それでも 送る」で送れる（相対 TTL なら届く）。
- 一覧: 並び順と日付見出しを「この端末に届いた時刻」に変え、見出しは「今日 届いた」「きのう 届いた」「10月9日（木）に 届いた」。カードの時刻は created_at のまま。created_at が未来または 24 時間以上前なら時刻を灰色にし 16pt「（出した スマホの 時計が ずれている かもしれません）」。固定枠（C03）は created_at 順のまま。
- HELLO 直後に 0x04 TIME（u32 現在エポック秒）を送る（v1 は不明 type を状態判定前に読み飛ばす）。差の中央値が 1 時間を超えたら状態帯に「この スマホの 時計が 近くの 端末と 2日 ずれています」、診断画面に「近くの端末との 時計の差」。

#### C13 前方互換
- 02 §2・§3 を v1 のうちに変える。(1) 封筒ヘッダ offset 0〜27 の位置と意味は将来版でも不変と明記。(2) 受信側の検証を 2 段に分ける。「中継できる条件」= magic 一致・ヘッダ 28 B 以上・body_len と実長一致・body_len ≤ 4,096・フレーム ≤ 8,192・expires_at ≥ created_at・hop < 64・期限内（C12 の相対判定）。満たせば version/kind/flags が未知でも生バイトのまま「不透明メッセージ」として保存・目録・中継（表示も伸長もしない。hop+1 は offset 23 を直接書き換え。期限・削除順はヘッダだけで判定）。「表示できる条件」= 現行の全検証（伸長上限 4,096 B は表示時に適用）。envelope.dart decode の kFlagsReservedMask・不明 kind の破棄、NoticeBody/GroupInfoBody の expectEnd（末尾の余りフィールド拒否）を「無視」に緩める。

- (4) 01 §4 に N-5「旧版の端末は新版の投稿を中継できること」。01 §5 とプライバシーポリシーに「新しい版のお知らせは内容を確認せずに運ぶ」。

#### C17 中継役同士の交換
- HELLO caps bit1 = 中継役（C04 と連動）、bit2 = 参加グループ一覧あり（中継役だけが立てる）。

#### C20 本文の消去
- 02 §2 tombstone の受信処理を「対象 notice の body（sender_name・title・place・text）を端末から削除し、msg_id・group_id・kind・category・created_at・expires_at・hop だけの空殻（stub）として残す」に変える。空殻は INVENTORY には載せる（再受信を防ぐ）が MESSAGE では送らない（messagesMissingFrom から除外）。tombstone 自体は従来どおり対象 +24 時間保持・中継する。
- 本文削除時は store_file.dart の rewrite（全置換）を必ず実行し、ディスク上の add レコードからも本文を落とす（_compactThreshold を待たない）。stub レコード型を追加し compaction でも空殻として書き直す。
- C10 の role 規則で適用されない tombstone では消さない。本文を残すのは発信者本人の端末（「取り消しました」帯。C14 の「前に 出した お知らせから 作る」の候補からは除く）と、そのグループの公式端末（C09。再投稿で復旧できるように）。
- 04 §4.2 行 5「取り消し済みは灰色＋帯」は受信端末では廃止し一覧から消す。取消確認文「終わった お知らせは『終わりました』を 使ってください。取り消すと 本文が 近くの スマホからも 消えます（届くまでに 時間が かかります）」。空殻を通知から開いたときは既存の「見つかりません」。
- 01 §5 に「取り消しは端末からの消去を伴うため偽造時の影響が大きい。公式は再投稿で回復できる」。

#### C21 困っています（条件付き採用）
- ホームの主ボタン「お知らせを 書く」の下（投稿不可ならその位置）に副ボタン「困っています」を、参加中グループのどれかが policy bit2（困りごとを 受け付ける）を立てているときだけ出す。既定は OFF（本部が係を置いてからオンにする。グループ作成・詳細のスイッチ）。
- 画面 1 枚: ①6 択の大ボタン「水・食べ物が ない」「薬・医療が 必要」「動けない・助けが 必要」「トイレが 使えない」「電気・ガスが 止まっている」「その他（1 行）」 ②場所（任意、40 文字。ヒント「町名と 目印だけ（番地は 書かない）」） ③人数「1人／2〜3人／4人以上」 ④主ボタン「送る」→ 確認「近くの スマホを 通って、避難所の 係の人に 届きます。名前は 送りません。届くまで 時間が かかります。急ぐときは 近所の 人にも 声を かけてください」。見出しは自動「【〇〇町2丁目】薬・医療が 必要（2〜3人）」、本文なし、sender_name 空。
- 封筒は kind=3 help（category=14 支援要請、role=0、TTL 24 時間固定、flags なし）。同じ 6 択を 30 分以内に再送しようとしたら「さきほど 送りました。受け取りの 返事を 待ってください」で封筒を作らない。
- 受信側: そのグループで公式・スタッフ（C09）の端末だけが一覧の切替に「困りごと（N 件）」を出して表示（visibleNotices に kind と役割の条件）。住民端末は保存・中継のみ。暗号化はないので秘匿ではなく表示上の分離であることを 01 §5 に明記。
- 運営端末の詳細に主ボタン「受け取りました」→ kind=4 ack（supersedes = 元 msg_id、本文空、TTL = min(元の expires_at + 24 時間, 48 時間)。message_store.dart は kind=4 を「置き換え」扱いにしない）。元の端末は ack を受けると詳細に「〇〇市 防災課 が 受け取りました（午後3時10分）」と OS 通知。
- 導入: C13 と同時または後（v1 の decode は不明 kind を捨て中継もしない）。C09 の後。手引きと利用規約に「『受け取りました』は対応の約束ではなく、担当の割り当ては本部の紙で行う」。
- operation 視点の不採用意見（健康状態＋場所の平文中継は 07 C1 (3) と衝突、本部が対応責任を負えない）は残る懸念として手引きに載せ、オンにするかは自治体の判断とする。
- **v2.1 の拡張（2026-10-23、実装済み）**: 住民の知らせを「助けて（SOS）」「無事です」「家に います（在宅避難）」「困っています」の 4 種類にした（docs/02 §2 の help ext、docs/04 §4.7）。
  - SOS は本部・スタッフ端末で urgent 通知と赤帯。無事です・在宅避難は任意の名前（安否を名簿と照らすため。SOS・困りごとは名前なしのまま）と人数・けが人の有無。在宅避難は困りごとも選べる。見出しの場所は入れず place に分けた（120 バイトに収めるため）。
  - 公式・スタッフはお知らせに「返事の ボタン」を付けて安否確認を出せる（notice ext bit0）。住民は「受け付ける」がオフでもボタンで返事でき、運営端末は安否確認ごとに集計（種類別の件数・人数、未返事）・まとめて「受け取りました」・文章でコピーができる。
  - 送った本人は「送った 知らせ」で状態を見て、取り消せる（中継端末では本文を消す）。送信順と先出しで help・ack を notice より前にした（小さく急ぐため）。
  - 残る懸念: 名前と場所が平文で中継される点は C21 の懸念と同じ（表示上の分離であり秘匿ではない）。同じ人の重複送信は区別できないので人数は目安。偽の SOS を防ぐ手段はない（端末側の送り直し制限だけ）。

#### C24 group_info の拡張
- 02 §2 group_info body に 5 番目のフィールド ext（u16 len ‖ code_digest 8 B ‖ generation u16 ‖ successor uint24）。code_digest = SHA-256(本部コード 8 桁 ASCII) 先頭 4 B ‖ SHA-256(スタッフコード) 先頭 4 B。generation はコード作り直し・引っ越しごとに +1 し、受信側は 世代 → created_at の順で新しい方を採用（C12 の時計ずれで古い方が勝つのを防ぐ）。successor は後継の参加コード（0 = なし）。policy bit1 = 閉鎖。GroupInfoBody の encode/decode を「5 番目は省略可」にし 4 フィールドの旧形式も受ける。C13 を含むビルドの配布前に入れる。
- 検証: groups.dart elevate は group_info 受信済みなら入力コードのダイジェスト一致を要求し、不一致は「番号が ちがいます」。本部コードは一致必須、スタッフコードは未受信なら受理し後で再検証（C09）。ダイジェスト 4 B は 10^8 通りの総当たりがスマホで数秒なので「任意の 8 桁で公式になれる」「漏れたコードを止められない」の是正に留まり、なりすまし対策ではないことを 01 §5 に明記（暗号・署名は使わない）。
- 本部端末のグループ詳細に副ボタン「コードを 作り直す」（本部・スタッフの 8 桁を新発行 → generation+1 で group_info 再発信。以後の新規昇格にだけ効き、既に昇格した端末は残る。自動降格はしない。画面と手引きに明記）と「新しい グループに 引っ越す」（漏えい時の手順。新グループ作成 → 旧 group_info を closed=1・successor=新コードで再発信、期限 365 日。旧グループは一覧で「終了（引っ越し先 123 456）」）。6 桁の参加コードは年 1 回更新しない。
- 住民側: 参加中グループの closed group_info を受けたらホーム上部に文字だけの帯「『〇〇市 防災課』は 新しい 参加コードに 変わったと 届きました。広報紙の 番号と 同じときだけ、グループ画面から 6 桁を 入れてください」（参加ボタンも自動の leave も置かない）。OS 通知 1 件。
- 「グループを 作る」に「問い合わせ先・ひとこと（なくても よい、100 文字まで）」欄を足し description に載せ、グループ詳細と参加画面（C22）に表示。
- 落とす: 自動降格、1 タップ参加ボタン、「住民に 配る 案内を 作る」（C16 の A4 テンプレートで代替）、Universal Links の QR（heiji-c6、サーバが要る）。QR は kairanban:123456 のまま。

#### C25 ふりがな・多言語（could、3 段階）
- ①設定「ふりがな: つける / つけない（既定: つけない）」。つけるとき、画面の固定文言・ボタン・種別名・テンプレートは同梱の読みデータで ruby 表示、見出し・本文は lib/core/readings.dart（kDictionaryV1 の約 600 語に読みを付けた別テーブル。kDictionaryV1 は変更しない）に最長一致した語だけ ruby。Flutter に ruby 組版はないので WidgetSpan で自作。ruby 時の行間 1.6 → 2.0。R-21 に「ふりがなを選べる」。
- ②notice body の 5 番目フィールド（template_id 1 B＋穴埋め値）: 見出しがテンプレートの { } を埋めただけなら付け、title には日本語の完成文をそのまま入れる。受信側（C25 端末）は自分の言語の定型文で組み立て直す（例: Water is being distributed at 〇〇 Park）。旧版は C13 の余りフィールド無視で日本語を表示。各言語の定型訳を docs に一覧化し、自治体の多文化共生担当が確認できる形にする（訳の責任主体を明確にする）。
- ③app.dart の supportedLocales を ja / en / zh-Hans / vi / pt / ko に広げ OS 言語に追従、設定「ことば / Language」。種別名・役割名・ボタン・案内文・日時表記（日本語以外は 24 時間制「15:20」）を翻訳。
- 自由文本文の自動翻訳はサーバなしでは行わないことを 01 §6 に明記。flags bit3 は使わず予約のまま。英語併記欄 text_alt（hairyo-c6）は帯域を最大 2 倍にするため不採用。
- value 視点の不採用意見（中心利用者は漢字が読める、行間 2.0 で情報量が減る）を踏まえ、既定オフ・OS 追従で v2 の最後に入れる。
